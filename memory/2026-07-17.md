### Session Bloat
- 12 sessions on disk consuming 495MB; trajectory files are the primary driver

### Kaizen Ideas
1. Session Trajectory Pruning — 495MB is 3x threshold; trajectory.jsonl files accumulate per session run
   Root cause: trajectory capture is enabled globally and never purged
   Fix: Add a cron job to  or configure trajectory sampling to run less frequently

2. trustedProxies Empty — gateway.bind=loopback but if a reverse proxy is ever added, spoofing possible
   Root cause: config was set to loopback without populating trustedProxies
   Fix: Set gateway.trustedProxies to your LAN subnet (e.g., 192.168.1.0/24) or reverse proxy IP if/when a proxy is introduced

3. sandbox.mode=off — runtime/process exec tools exposed without sandbox
   Root cause: intentional for local single-user; but Telegram groupPolicy=open makes this a larger attack surface
   Fix: Keep sandbox=off for now if you trust Telegram group members; revisit if groupPolicy changes
